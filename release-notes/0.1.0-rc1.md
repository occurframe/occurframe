## What Occurframe is

Occurframe is an executable conformance oracle for recurring-time semantics. It
is not a scheduling engine.

It sends authored corpus vectors to an external recurrence implementation over a
process protocol, records exactly what that implementation answered, and scores
the answer against a versioned expectation. It contains no cron or RRULE parser,
no evaluator, and no scheduling execution of any kind. It computes nothing about
recurrence itself; that is the point of an oracle.

## What is included

- `occurframe` and `oframe` — two names for one implementation, byte-identical in
  options, output and exit codes — built for **Windows x86_64**, **Linux x86_64**,
  **macOS arm64** and **macOS x86_64**.
- The generated corpus `1.0.0-rc2` distribution, so a run needs no network
  access, plus the runner protocol schema.
- The full public documentation set: getting started, CLI reference, writing a
  runner, interpreting results, releases, and known contradictions.
- `examples/minimal-runner/` — a complete, runnable protocol integration example.
  It is a protocol example only: not a recurrence engine and not a conformance
  reference.
- The certified RC2 differential report and cell-level matrix, plus the
  certification manifest and the observed certification environment.
- The adapter identity registry. No third-party engine runtimes are
  redistributed.
- `release-manifest.json`, `VERSION`, `SHA256SUMS`, `LICENSES.md`,
  `DEPENDENCIES.json` and `THIRD-PARTY-NOTICES.md`.

## `test` command status

`test` is the only implemented command:

```text
occurframe test --engine <configured-build-id> [--corpus PATH] [--family F]...
                [--tzdb REQUIREMENT] [--format text|json|junit]
```

Output is text on a terminal and deterministic JSON when stdout is redirected; an
explicit `--format` always wins. JSON has canonical key ordering and is
byte-identical across runs of identical inputs. JUnit maps conformant and
admissible to success, non-conformant to failure, unsupported and open/unscored
to skipped, and engine error, timeout and runner failure to error.

Exit codes: `0` conformant, `1` semantic non-conformance or engine error or
timeout, `3` usage, `4` environment/infrastructure. `4` takes precedence over
`1`, because a run whose evidence is untrustworthy is not a statement about the
engine. Codes `2` and `5` remain reserved and are never produced.

## Corpus RC2 identity

```text
version:          1.0.0-rc2
canonical digest: 4804772d20fb36c7329b2c5f2f28e264d9bc00b11e407e76d9836fc38cd80470
vectors:          184
```

The corpus is authored in the separate `occurframe/corpus` repository and remains
the semantic authority. The tooling pins that version, digest and vector count and
refuses to run against anything else, including through an explicit `--corpus`.
Generated observations, matrices, reports and packed corpus data are derived
artifacts, never normative source. The corpus is itself a release candidate: it
is `1.0.0-rc2`, not stable `1.0.0`.

## Runner protocol 2.0

Integration is a process boundary, not a plugin interface: newline-delimited JSON
over stdin/stdout, with `hello`, `case`, `started` and `result` messages and
exactly five terminal outcomes — `occurrences`, `accepted`, `rejection`,
`unsupported`, `engine_error`.

A runner asserts its identity in `hello`, and Occurframe refuses to attribute any
observation to a build whose `hello` disagrees with its registry entry: runner and
engine identity and provenance, runtime language/name/version, capability list,
dialect IDs, semantic-profile claims and timezone-database provenance must all
match exactly. Registries may live anywhere on the filesystem; relative launch
paths resolve against the registry's own directory. See
`docs/WRITING-A-RUNNER.md`.

## Certified evidence population

This release republishes the already-certified RC2 differential evidence. It is
not a fresh measurement taken for the release.

| | |
| --- | ---: |
| Configured historical builds | 25 |
| Reproducible builds | 23 |
| Provenance-blocked Ruby builds | 2 |
| Vectors | 184 |
| Observations | 4,232 |
| Semantic-divergence vectors | 163 |
| Normative-violation vectors | 76 |
| Engine errors | 8 |
| Timeouts | 1 |
| Unsupported cells | 2,099 |

Unsupported cells, engine errors and timeouts are **excluded from semantic-answer
grouping**. The 163 figure counts vectors on which the reproducible builds did not
all produce the same semantic answer.

**163 divergent vectors does not mean 163 engine defects.** Divergence spans
named policy differences, named dialect differences, standard ambiguity, known
implementation divergence and timezone-database provenance differences, as well
as normative violations. No engine ranking or overall quality score is published,
and none should be derived. See `docs/INTERPRETING-RESULTS.md`.

The canonical certification environment and provenance ship in
`certification/environment.json` and `certification/certification-manifest.json`.

## Known limitations

- Only `test` is implemented; see the reserved-command contradiction below.
- No recurrence engine, cron/RRULE evaluator or scheduling execution is included,
  by design.
- Third-party engine runtimes are not bundled. Testing a real engine requires a
  runner and a prepared runtime you provide.
- The corpus is a release candidate; expectations may still be corrected with
  reviewed evidence before stable `1.0.0`.
- `--no-color` and `NO_COLOR` are accepted but currently have no observable
  effect, because the text renderer emits no colour.
- Binary reproducibility is measured and reported per release rather than
  assumed; see `docs/RELEASES.md` for the three distinct reproducibility
  properties.

## Ruby provenance limitation

`ruby.fugit` and `ruby.ice_cube` are configured but `unreproducible_provenance`:
Phase II did not record the exact historical `concurrent-ruby` dependency that
`tzinfo` required. No contemporary dependency, engine or Ruby version was
substituted to fill the gap.

The certified population is therefore 23 measured builds out of 25 configured,
and that shortfall is stated in the public report rather than concealed by
reporting 23 as the total. Occurframe refuses to execute a
provenance-blocked build at run time: evidence that cannot be reproduced is not
evidence.

## Reserved-command contradiction

Research II freezes `test`, `explain`, `classify` and `occurrences` as the public
command names, and also closes the production recurrence-engine gate. The frozen
meanings of `explain`, `classify` and especially `occurrences` appear to require
evaluator behaviour, which conflicts with **GO — ORACLE ONLY**.

This prerelease implements only `test`. The other three names are reserved and
return a not-yet-available usage error; they are not redirected, faked or
evaluator-backed. The contradiction is unresolved and needs explicit product
doctrine before any reserved command can be implemented. See
`docs/KNOWN-CONTRADICTIONS.md`.
