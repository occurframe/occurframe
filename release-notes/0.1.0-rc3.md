Occurframe tooling: 0.1.0-rc3

## Authority boundary

Protocol 3.0 sends a dedicated case projection to runners. Expected answers,
admissible answer sets, scoring mode, classification, rationale, normative
evidence and tags remain inside the Occurframe authority. All five first-party
runner families use the same `hello → case → started → result` lifecycle.

Certification records the actual clean corpus and tooling source revisions
independently from the canonical corpus digest. A declared corpus revision is a
comparison target, never a substitute for the checkout that was measured.

Runner processes execute under `hermetic_allowlist_v1`: the executable is
resolved first, the inherited environment is cleared, and only the deliberate
platform minimum, `TZ=UTC`, the C locale and declared build variables are
granted. Variable names are recorded; secret values are not.

`c0a9cf0587c02ce5022cbb94d060e14d5b9d6f99c3210e512965f35062c4dfe0`.

the protocol transport change, and zero cells are unresolved.

## Product boundary

Occurframe remains **GO — ORACLE ONLY**. The shipped semantic surface is:

```text
occurframe test
oframe test
```

No recurrence engine, scheduler, worker, queue or persistence layer is included.
Third-party engine runtimes are not redistributed. `ruby.fugit` and
`ruby.ice_cube` remain explicitly provenance-blocked rather than being replaced
with contemporary dependencies.

## Exit codes

```text
0  every scorable selected vector conforms
1  semantic non-conformance, engine error, or engine timeout
3  usage error
4  environment/provenance/infrastructure failure
```

The corpus and specification remain release candidates. Owner review, merge,
tagging and publication are deliberately outside the automated gate.
